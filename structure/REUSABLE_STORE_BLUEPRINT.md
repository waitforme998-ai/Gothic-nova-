## 1. Engine Core vs Client-Specific Assets

When starting a project for a new business, know which files stay untouched and which get customized:

```
[ UNTOUCHED ENGINE CORE ] (90% of Code)
├── supabase-engine.js      -> Realtime sync, SWR caching, safe storage, database bridge
├── api/sitemap.js          -> Dynamic Google XML sitemap generator
├── search-engine.js        -> Instant catalog indexing and search
├── scroll-engine.js        -> Fluid scrolling and ambient effects
├── vercel.json             -> Edge caching, cleanUrls routing, security headers
└── robots.txt              -> Crawler policy and canonical sitemap link

[ CLIENT-SPECIFIC CUSTOMIZATIONS ] (10% of Code)
├── index.html              -> Brand titles, hero text, logo, favicon, SEO meta tags
├── admin.html              -> Admin dashboard branding & client logo
├── style.css               -> Color tokens, theme accents, brand typography
└── assets/                 -> Client hero backgrounds, logos, cutouts
```

## 2. The 3-Step Client Setup Protocol

### Step 1: Initialize Supabase (Free Tier)
1. Go to [supabase.com](https://supabase.com) and create a free project (e.g. `client-leather-store`).
2. Navigate to **SQL Editor** and run this SQL to create the single orders table:
   ```sql
   create table public.gn_orders (
     id bigint generated by default as identity primary key,
     order_number serial,
     customer_name text not null,
     customer_phone text,
     shipping_address text,
     city text,
     items jsonb default '[]'::jsonb,
     total_amount numeric,
     delivery_charges numeric default 0,
     advance_deposit numeric default 0,
     status text default 'PENDING',
     payment_method text default 'COD',
     created_at timestamp with time zone default timezone('utc'::text, now()) not null,
     updated_at timestamp with time zone default timezone('utc'::text, now()) not null
   );

   -- Enable Realtime
   alter publication supabase_realtime add table public.gn_orders;
   ```
3. Navigate to **Storage** → Click **New Bucket**:
   * Name: `product-media`
   * Check **Public Bucket** = `ON`
   * Save.
4. Copy your **Project URL** and **Anon Public Key** from **Settings → API**.

## 3. Deployment & Domain Routine (Namecheap + Vercel)

1. **Push Code to New GitHub Repo:**
   ```bash
   git init
   git add .
   git commit -m "feat: initial client release"
   git remote add origin https://github.com/your-username/client-store-name.git
   git push -u origin main
   ```
2. **Import to Vercel (Free):**
   * Go to [vercel.com](https://vercel.com) → Click **Add New Project** → Select your repo.
   * Framework Preset: `Other` (Static).
   * Click **Deploy**.
3. **Connect Namecheap Domain:**
   * In Vercel Project Settings → **Domains** → Add `clientdomain.com`.
   * In Namecheap → **Advanced DNS** → Add two records:
     * **A Record:** Host: `@`, Value: `76.76.21.21`
     * **CNAME Record:** Host: `www`, Value: `cname.vercel-dns.com`
4. The store is now live with automatic SSL, global CDN edge caching, and automated builds!

## 4. Google Search Console Handover Protocol

1. Go to [search.google.com/search-console](https://search.google.com/search-console).

3. Add the TXT verification record to Namecheap **Advanced DNS**.

## 6. Client Customization Framework (Feature Flags & Schema Extensibility)

When different businesses have unique operational requirements, **never rewrite the engine**. Use the two-tier architectural pattern below to toggle features and extend data contracts instantly:

### 6.1 The Feature Flag Engine (Toggle Features in 1 Second)
Add a centralized `STORE_CONFIG.features` block:

```javascript
const STORE_CONFIG = {
  features: {
    tarotGamification: false,     // Disable gamified wheel for luxury, leather, or perfume brands
    advanceDepositSlip: true,     // Require Rs. 500 advance deposit verification for COD
    sizeAndColorVariants: true,   // Enable Size / Color dropdown on PDP modal (clothing/shoes)
    cityBasedDelivery: true,      // Karachi: Rs. 150 / Other cities: Rs. 300
    directWhatsAppCheckout: false // Bypass checkout modal; sends cart summary straight to WhatsApp
  }
};
```

**Implementation Pattern in Storefront:**
```javascript
// Example: Hide Tarot button if client brand does not want gamification
if (!STORE_CONFIG.features.tarotGamification) {
    const tarotBtn = document.getElementById('tarotTriggerBtn');
    if (tarotBtn) tarotBtn.style.display = 'none';
}
```

---

### 6.2 Zero-Migration JSONB Extensibility
Because Supabase PostgreSQL stores `items` as a native `JSONB` document, you can add custom client properties **without touching database schemas or running SQL migrations**:

* **Clothing / Shoe Brand:** Add `sizes: ["S", "M", "L", "XL"]` to the product object. When purchased, `selectedSize: "L"` persists inside `items` automatically.
* **Perfume Brand:** Add `volumes: ["50ml", "100ml"]`. When purchased, `selectedVolume: "100ml"` persists automatically.
* **Custom Notes / Engravings:** Add `customEngravingText` to cart items with zero schema changes.
